* The easy layer: ~(uri easy)~

Give it a URI as a string. Get back a record you can ask questions.

#+begin_src scheme
(import (rnrs) (uri easy))

(define u (string->uri "https://user@Example.COM:8443/a/caf%C3%A9?q=a%26b&tag#top"))

(for-each (lambda (x) (write x) (newline))
          (list (uri-scheme u)
                (uri-host u)
                (uri-port u)
                (uri-path u)
                (uri-path-segments u)
                (uri-query-pairs u)
                (uri-fragment u)))
#+end_src

#+begin_example
"https"
"example.com"
8443
"/a/caf%C3%A9"
("a" "café")
(("q" . "a&b") ("tag" . #f))
"top"
#+end_example

Run it from the repository with
~scheme --libdirs "src:vendor/byte-machine/src" --script easy.scm~.

** Parsing

| ~string->uri~           | an absolute URI: it must have a scheme |
| ~string->uri-reference~ | absolute or relative                   |
| ~string->relative-ref~  | relative only                          |

All three check the whole URI against RFC 3986. A bad one raises a
~&uri-error~, which says what is wrong and where:

#+begin_src scheme
(guard (e ((uri-error? e)
           (list (uri-error-reason e) (uri-error-offset e) (uri-error-input e))))
  (string->uri "http://a b/"))
;; => (invalid-reg-name 8 "http://a b/")
#+end_src

The offset counts characters. To ask without catching anything, use
~uri-string?~.

RFC 3986 allows only ASCII, so a URI with ~é~ in it is refused. Encode text
before you put it in a URI:

#+begin_src scheme
(uri-encode "café")
;; => "caf%C3%A9"
#+end_src

** Reading

Each accessor returns the text as it was written, so nothing is lost. There
are two exceptions: ~uri-scheme~ and ~uri-host~ come back lowercase, because
you mostly read them to compare them.

~#f~ means the part is missing. ~""~ means it is there, but empty:

#+begin_src scheme
(uri-query (string->uri "http://a"))
;; => #f
(uri-query (string->uri "http://a?"))
;; => ""
#+end_src

~uri-port~ is a number, or ~#f~ when there is none.

** Decoding

~uri-path-segments~, ~uri-query-pairs~ and ~uri-form-pairs~ split first and
decode after, so an encoded ~/~ or ~&~ stays inside its piece. A key with no
~=~ gets the value ~#f~. ~uri-form-pairs~ also reads ~+~ as a space, the way
HTML forms write it:

#+begin_src scheme
(uri-form-pairs (string->uri "http://a?q=a+b&x=%2B"))
;; => (("q" . "a b") ("x" . "+"))
#+end_src

Decoding must give UTF-8. If it doesn't, you get an error, never a ~�~:

#+begin_src scheme
(guard (e ((uri-error? e) (uri-error-reason e)))
  (uri-decode "%FF"))
;; => invalid-utf-8
#+end_src

** Resolving, normalizing, comparing

#+begin_src scheme
(uri->string (uri-resolve "http://a/b/c/d" "../x?y"))
;; => "http://a/b/x?y"
(uri->string (uri-normalize (string->uri "HTTP://A/%7Ex/./y/../z")))
;; => "http://a/~x/z"
(uri=? "HTTP://a/%7Euser" "http://a/~user")
;; => #t
#+end_src

~uri->string~ turns a record back into its string. ~uri-normalize~ removes
~.~ and ~..~ everywhere except a relative path such as ~../b~, where they
point somewhere and so stay. ~uri=?~ compares after normalizing.

** When to use the byte-level libraries

~(uri easy)~ checks everything and allocates freely. A server reading URIs off
the wire should use ~(uri collect)~ instead: it streams, reuses its memory,
and works in bytes (see the README). ~uri->components~ and ~components->uri~
move between the two.
