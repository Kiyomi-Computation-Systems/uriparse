* uriparse

[[https://github.com/Kiyomi-Computation-Systems/uriparse/actions/workflows/ci.yml][https://github.com/Kiyomi-Computation-Systems/uriparse/actions/workflows/ci.yml/badge.svg?branch=main]]

A URI parser for Chez Scheme, written in portable R6RS. It follows
[[https://www.rfc-editor.org/rfc/rfc3986][RFC 3986]].

#+begin_quote
✨ *AI Disclosure:* LLMs are used extensively in the planning and development of this project.
#+end_quote

** Why

uriparse is built for servers that read URIs straight off the wire.

- *Bytes in, bytes out.* A URI is parsed as a bytevector, not a string, so
  nothing is decoded or guessed before the parse.
- *Streaming.* Input can arrive in any number of chunks, and the result is the
  same however it was split.
- *Reusable.* One collector can serve every request on a connection. Resetting
  it reallocates nothing.
- *No copies to validate.* A check can run over a range of your own buffer in
  place.
- *Lenient parsing, strict validation, kept apart.* ~uri-parse~ splits whatever
  it can. ~uri-parse-validate~ rejects exactly what the RFC grammar rejects. You
  pick the one you need.
- *Absent is not empty.* ~http://a~ has no query and ~http://a?~ has an empty
  one, and the results say so: ~#f~ for absent, an empty bytevector for empty.

If you just have a URI in a string, you don't need any of that: ~(uri easy)~
takes strings and gives back strings.

** What it does

- *Read URIs as strings.* ~(uri easy)~ parses a string into a record and
  answers with strings: the host, the port as a number, decoded path segments
  and query pairs. It also resolves, normalizes and compares.
- *Split queries.* ~(uri query)~ reads the ~key=value&…~ pairs out of a query.
  It splits first and decodes after, so an encoded ~&~ stays in its value.
- *Parse.* Split a URI into scheme, authority, path, query and fragment. Three
  modes: an absolute URI (~uri~), a relative reference (~relative-ref~), or
  either (~uri-reference~).
- *Validate.* Check each component's characters, plus the authority's userinfo,
  host (registered name, IPv4, IPv6 or IPvFuture) and port.
- *Resolve.* Resolve a relative reference against a base URI, including
  removing ~.~ and ~..~ segments, and turn components back into a URI. Every
  resolution example in RFC 3986 passes.
- *Normalize.* Lowercase the scheme and host, uppercase percent-encoding hex,
  and decode percent-encoded characters that never needed encoding.
- *Parse CONNECT targets.* Read the bare ~host:port~ form an HTTP ~CONNECT~
  request uses (RFC 9112's authority-form).

** Using it

The libraries live in ~src/~ and depend on
[[https://github.com/Kiyomi-Computation-Systems/byte-machine][byte-machine]],
included as a git submodule in ~vendor/byte-machine~.

#+begin_src sh
git clone --recurse-submodules https://github.com/Kiyomi-Computation-Systems/uriparse.git
#+end_src

Read a URI from a string:

#+begin_src scheme
(import (rnrs) (uri easy))

(define u (string->uri "https://user@Example.COM:8443/a/caf%C3%A9?q=a%26b&tag#top"))

(for-each (lambda (x) (write x) (newline))
          (list (uri-host u)
                (uri-port u)
                (uri-path-segments u)
                (uri-query-pairs u)
                (uri->string (uri-resolve u "../x?y"))))
#+end_src

#+begin_example
"example.com"
8443
("a" "café")
(("q" . "a&b") ("tag" . #f))
"https://user@Example.COM:8443/x?y"
#+end_example

[[file:docs/easy.org][docs/easy.org]] covers the rest of ~(uri easy)~.

A server works in bytes. Parse a URI and read its components:

#+begin_src scheme
(import (rnrs)
        (uri collect)
        (uri components))

;; The parser works on bytes, so the input is UTF-8.
(define result
  (uri-parse 'uri (string->utf8 "https://example.com/path?q=1#top")))

;; Print one component, or "<absent>" when the URI has none.
(define (show name bv)
  (display name) (display ": ")
  (display (if bv (utf8->string bv) "<absent>"))
  (newline))

(when (uri-parse-ok? result)
  (let ((c (uri-parse-components result)))
    (show "scheme"    (uri-components-scheme c))
    (show "authority" (uri-components-authority c))
    (show "path"      (uri-components-path c))
    (show "query"     (uri-components-query c))
    (show "fragment"  (uri-components-fragment c))))
#+end_src

#+begin_src sh
scheme --libdirs "src:vendor/byte-machine/src" --script parse.scm
#+end_src

#+begin_example
scheme: https
authority: example.com
path: /path
query: q=1
fragment: top
#+end_example

definition.

** Scope and limits

- ~uri-parse~ is deliberately lenient: ~http://a/b c~ parses. Run
  ~uri-parse-validate~ when you need the input to be a valid URI; it rejects
  that one with ~invalid-pchar~.
- Validation accepts exactly the inputs the RFC 3986 grammar accepts. This is
  tested against an exhaustive sweep of short inputs, the RFC's own examples,
  and a hand-written adversarial set.
- ~(uri normalize)~ does not remove ~.~ and ~..~ segments; resolution does. If
  you want both, normalize first and then resolve. ~(uri easy)~'s
  ~uri-normalize~ does both, in that order.
- ~(uri easy)~ accepts only ASCII, as RFC 3986 does: encode text with
  ~uri-encode~ before putting it in a URI. Its decoding must produce UTF-8:
  ~%FF~ raises ~invalid-utf-8~ instead of becoming ~�~.
- Resolution is strict: ~http:g~ resolved against ~http://a/b/c/d;p?q~ stays
  ~http:g~. The older, looser behaviour the RFC mentions is not supported.
- Recomposing gives back what was parsed. It does not repair components built
  by hand into something ambiguous, such as a scheme-less path whose first
  segment contains ~:~. Resolution can produce one such shape too: against a
  base with no authority, ~foo:/a~ and ~.//bar~ resolve to the path ~//bar~,
  which recomposes to ~foo://bar~, a URI whose authority is ~bar~. ~(uri easy)~
  writes that path as ~/.//bar~ instead, which names the same path and parses
  back unchanged.
- Only Chez Scheme is tested. CI runs on Linux amd64; development happens on
  macOS. Windows and arm64 are untested.

** Developing

*** Requirements

- Chez Scheme 10.4.1 or newer, the full system rather than Petite (the
  compiled test lanes need ~compile-program~)
- CMake 3.26 or newer

The build looks for ~scheme~, ~chez~ and ~chezscheme~, in that order. To point
it somewhere else:

#+begin_src sh
cmake --preset dev -DURI_CHEZ_EXECUTABLE=/absolute/path/to/scheme
#+end_src

*** Building and testing

#+begin_src sh
make            # list every target
make test       # the pull-request selection
make test-all   # every test
make no-scheme  # the CMake layer alone, on a machine with no Scheme
make check-akku # install with Akku as a consumer would (needs akku)
#+end_src

The Scheme examples in this README and in ~docs/~ are run by the tests, so
they print what they say they print. ~Akku.manifest~ describes the package for
the [[https://akkuscm.org/][Akku]] index; ~make check-akku~ installs it into a
throwaway project and checks that exactly the libraries in ~src/~ land.

*** Generated files

Two kinds of file are generated, committed, and checked by a test that
regenerates them and compares. Edit the source, not the output:

- ~src/generated/uri-scanner.sls~ comes from ~(uri grammar)~. Run
  ~make parser-refresh~ after changing the grammar.
- ~test/conformance/rfc3986/~ is extracted from the RFC text in ~test/vendor/~.
  Run ~make corpus-refresh~ after changing the extractor.
