** Status: v0.6.1 — released 2026-09-26

The scanner splits a URI reference into five components — scheme, authority,
path, query, fragment — for all three modes (M2), and ~(uri collect)~ assembles
them; the pure core percent decodes/encodes and applies RFC 3986 §6.2.2
syntax-based normalization (M5). It *resolves* references: ~(uri path)~ (§5.2.4
remove-dot-segments, §5.2.3 merge), ~(uri resolve)~ (§5.2.2 strict
transform-references) and ~(uri recompose)~ (§5.3) turn a base and a reference
into a target URI — and **all 42 rows of RFC 3986 §5.4 pass** (M6). Now the
round-trip property is *measured* (M7): ~parse → normalize → recompose → parse~
reaches a fixed point over every committed URI, so the pipeline is internally
consistent. It also *validates*: ~uri-parse-validate~ judges every component's
charset (M3) and the whole authority host grammar — userinfo, host as reg-name /
IPv4address / IP-literal → IPv6address / IPvFuture, and port (M4); ~(uri normalize)~
now folds *host* case too, completing RFC 3986 §6.2.2.1 (M4); and
~uri-parse-authority-form~ parses an RFC 9112 authority-form ~host:port~ CONNECT
target (M9). ~uri-parse~ itself stays lenient — validation is the separate
~uri-parse-validate~ pass. That validation is now *audited*: ~uri-parse-validate~
is recognizer-equivalent to RFC 3986 Appendix A per mode — it accepts a byte
string iff the bytes are that production — over an exhaustive small-input sweep,
the normative corpora, and an adversarial corpus, with **zero deviations**
([[file:.plans/decisions/0028-the-rfc-3986-conformance-audit-is-recognizer-equivalence-against-an-independent-whole-uri-oracle.md][decision 0028]],
[[file:.plans/decisions/0030-the-rfc-3986-conformance-audit-is-clean-recognition-equivalence-is-earned.md][decision 0030]]).
For a server reusing one parser per connection, ~uri-collector-reset!~ returns a
collector to its just-constructed state in place, with no reallocation (issue #11);
and ~uri-parse-result-validate~ applies that same audited validation to a parse
result — a reused collector's ~uri-collect-finish!~ or any other — so a validating
server judges the reused result with no re-parse (issue #18). A server that keeps a
component as a span of its own buffer (an origin-form path or query) judges its
charset in place with ~validate-component~ over ~[start, end)~, copying nothing
(issue #21), and judges a ~Host~ header value in place the same way with
~validate-authority~ over ~[start, end)~ (issue #24).
Standing behind it all (M1): the RFC's own vectors, the
loader that reads them, the comparator, the two-way ratchet, and the harness and
build layer.

What this project will *not* claim until it is measured:

- Not a blanket "RFC 3986 compliant". The *validation* recognizer is now audited
  conformant (above) — but that claim is *scoped*, not a whole-library grant. It
  is RECOGNITION (accept/reject) equivalence per mode, not an
  error-code/offset-equivalence claim (those are the M3/M4 lanes' own gates); the
  exhaustive sweep is bounded (length 5, a 12-byte alphabet), with deeper
  structures covered adversarially, not exhaustively; and ~uri-parse~ ITSELF stays
  a lenient splitter *by design* — it accepts bytes the ABNF rejects, and that
  split between the two entry points is the point, not a gap
  ([[file:.plans/decisions/0024-charset-validation-is-the-cores-over-the-split-components.md][decision 0024]],
  [[file:.plans/decisions/0025-the-host-grammar-is-the-cores-over-the-opaque-authority.md][decision 0025]],
  [[file:.plans/decisions/0030-the-rfc-3986-conformance-audit-is-clean-recognition-equivalence-is-earned.md][decision 0030]]).
- ~(uri normalize)~ does not remove dot-segments. It applies all of RFC 3986
  §6.2.2.1 — *scheme* case, *host* case (M4), uppercase hex, decode unreserved —
  but dot-segment removal is reference resolution's job (§5.2.4), and lives in
  ~(uri resolve)~, not the normalizer
  ([[file:.plans/decisions/0020-v01-normalizes-scheme-and-percent-and-defers-host-case.md][decision 0020]],
  [[file:.plans/decisions/0025-the-host-grammar-is-the-cores-over-the-opaque-authority.md][decision 0025]]).
- Resolution is *strict* (§5.2.2 with strict = true). ~http:g~ resolved against
  ~http://a/b/c/d;p?q~ is ~http:g~, not the RFC-1630 backward-compatible
  ~http://a/b/c/g~ — that partial-URI compatibility is out of scope
  ([[file:.plans/decisions/0015-errata-4547-and-5428-are-adjudicated-against-the-abnf.md][decision 0015]],
  [[file:.plans/decisions/0001-the-project-is-chez-uri-and-where-it-stops.md][decision 0001]]).
  A caller wanting a *normalized* target normalizes before resolving — decoding
  ~%2E~ to ~.~ manufactures dot-segments that resolution then removes
  ([[file:.plans/decisions/0021-reference-resolution-recomposes-at-m6.md][decision 0021]]).
- The round trip holds for every *parse output*, not for every hand-built
  component. ~(uri recompose)~ (§5.3) is a faithful inverse of ~(uri collect)~,
  but two scheme-absent shapes it can be *handed* do not survive it: a relative
  path whose first segment contains ~:~ (recomposes to a *scheme*) and a
  no-authority path beginning ~//~ (recomposes to an *authority*). §5.3 omits
  §4.2's disambiguating ~./~ on purpose; a relative-reference serializer that
  adds it is a v0.2 function above recompose
  ([[file:.plans/decisions/0022-the-round-trip-property-is-a-one-step-parse-recompose-identity.md][decision 0022]]).
- Not "portable". The source is R6RS and imports only ~(rnrs)~,
  ~(byte-machine ...)~ and its own libraries — asserted by a lane, not trusted
  — but no second implementation is in CI, and a property is measured or it is
  not claimed ([[file:.plans/decisions/0007-src-is-pure-r6rs-and-chez-is-confined.md][decision 0007]]).

** Parsing a URI

~(uri collect)~ splits a URI into its five components and ~(uri components)~ reads
them. The core is bytevectors throughout, so a URI goes in as UTF-8 bytes and each
field comes back as bytes — or ~#f~ when the component is *absent*, which is never
confused with present-but-empty.

#+begin_src scheme
(import (rnrs)
        (uri collect)
        (uri components))

;; Parse a URI. The core works in bytevectors, so the input is UTF-8 bytes.
(define result
  (uri-parse 'uri (string->utf8 "https://example.com/path?q=1#top")))

;; Print one component, or "<absent>" when it never appeared (absent, not empty).
(define (show name bv)
  (display name) (display ": ")
  (display (if bv (utf8->string bv) "<absent>"))
  (newline))

(when (uri-parse-ok? result)
  (let ((c (uri-parse-components result)))
    (show "scheme"    (uri-components-scheme c))
    (show "authority" (uri-components-authority c))
    (show "path"      (uri-components-path c))
    (show "query"     (uri-components-query c))
    (show "fragment"  (uri-components-fragment c))))
#+end_src

Run it against the source libraries — ~src~ and the vendored ~byte-machine~:

#+begin_src sh
scheme --libdirs "src:vendor/byte-machine/src" --script parse.scm
#+end_src

#+begin_example
scheme: https
authority: example.com
path: /path
query: q=1
fragment: top
#+end_example

The mode is ~uri~ (an absolute URI); ~relative-ref~ and ~uri-reference~ are the
other two. Validating the component charsets and the host grammar is
~uri-parse-validate~ (parse and judge in one call), or ~uri-parse-result-validate~
to judge a result you already have — a reused collector's ~uri-collect-finish!~ —
without re-parsing. To judge one component's charset by itself, ~(uri charset)~'s
~validate-component~ takes the component's name, a bytevector, and an optional
~start~ and ~end~, and reports the first bad byte relative to ~start~. ~(uri host)~'s
~validate-authority~ does the same for an authority (~userinfo@host:port~), and
~authority-host-span~ gives the host's bounds within it, again relative to ~start~.
Parsing a bare
~host:port~ CONNECT target (RFC 9112 authority-form) is ~uri-parse-authority-form~.
Resolving a reference against a
base, normalizing, and recomposing live in ~(uri resolve)~, ~(uri normalize)~ and
~(uri recompose)~.

** The corpus

[[file:test/conformance/rfc3986/][test/conformance/rfc3986/]] is *derived*, not authored: extracted from
[[file:test/vendor/rfc3986.txt][the vendored RFC text]] by ~cmake/UriCorpus.cmake~, with the source's digest
recorded in ~PROVENANCE~. ~make corpus-refresh~ rewrites it and a registered
lane re-derives and compares, so a vector edited by hand reddens rather than
surviving. RFC 3986 §5.4 is the only normative vector set this project has, and
M6 is gated on all 42 of its rows passing.
